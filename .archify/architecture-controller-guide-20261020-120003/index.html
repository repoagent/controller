v1 contract · #30
Approved policy: #31 replaces the original broker browser/personal-approver model. Approval belongs to the repository. The install scripts create/reuse a GitHub Environment and write its nonsecret enrollment variable through the operator’s host authority. The user chooses both names. Controller tokens cannot modify approval; host credentials never enter the broker or controller.

GitHub Environment name

User-selected, for example repoagent. Preserve existing rules, secrets and unrelated variables when reusing it. This is separate from an Azure Container Apps environment.

Approval-variable name

User-selected, for example APPROVED_CONTROLLER. The value binds the controller ID and fresh enrollment fingerprint to the exact repository/App/profile. It contains no device secret.

GitHub Environment settings require adequate setup authority and supported repository-plan features. Broker reads use separately scoped GitHub permissions; controller v1 runtime profiles stay unchanged. GitHub variable API · Environment availability

The scripts perform the setup. Both names have command-line inputs, interactive prompts and saved defaults for reruns. The host GitHub identity creates the environment/variable, not the controller. A copied public marker or pending secret alone cannot activate enrollment; the broker independently reads the exact GitHub approval and requires private possession proof.
