# Use independent semantic component releases

Controller and credential broker releases use independent semantic versions proposed by pinned Release Please, rather than treating CI run IDs, source SHAs or upstream tool versions as compatibility versions. This refines ADR 0011's baseline-release contract: a controller native archive and public image share the approved controller version and exact offline notes, while operators still adopt immutable images deliberately. Protocol and storage schemas remain separately versioned.

Actual runtime-file ownership, including shared build inputs, is projected into logical component paths before Release Please splits commit history. This preserves independent component cutoffs and keeps Conventional Commit scopes descriptive. A separate artifact workflow verifies source, compiled version, notes and digest before publishing completed metadata; provisional semantic release records are never advertised by the dashboard as usable images. Retaining legacy v1 identities avoids inventing a semantic ordering for old run-based releases. We chose this over a second version authority or linked component versions because both would make compatibility and independent broker delivery ambiguous.
