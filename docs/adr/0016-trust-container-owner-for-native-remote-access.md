# Trust container access for native Codex owner access

Accepted on 2026-10-31 for [#332](https://github.com/repoagent/controller/issues/332), following the operator's clarification. This supersedes ADR 0015 and the administrator/tool isolation and preexecution desktop-admission restrictions in ADR 0014. Its shared CLI, private Unix HTTP transport, explicit instance binding, privacy and executable migration decisions remain in force.

The operator with access to the controller's container or native host may enable Codex native remote access on its existing owned runtime and pair the Codex account owner's desktop. The main use is observing sessions, with occasional trusted direct interaction. Normal container/controller identity and host/container root may administer the private socket. We do not require a separate identity for agent tools, a desktop read-only mode, a provider preexecution veto or arbitration of competition between the owner and RepoAgent. Their absence does not make remote access unavailable.

Remote commands implement actual enable, pair, status, client listing, targeted revocation and disable through the existing runtime connection. Intent defaults to disabled and survives ordinary restarts; outcomes distinguish intent, observations and uncertainty. Pairing codes are private caller output. The controller observes desktop turn lifecycle for existing work/status/checkout accounting, without routing manual desktop commands through the Discussion scheduler. Desktop access retains full native capabilities and is not advertised as enforced read-only access. Existing controller processing, runtime ownership and authority-loss termination remain intact.
