# Keep broker GitHub tokens in request memory

Accepted on 2026-11-02 for [#342](https://github.com/repoagent/controller/issues/342). Mint fresh runtime and internal verifier tokens per broker request and retain neither their values nor issuance outcomes in storage. Failed or uncertain requests discard their temporary state; a later controller request authenticates and verifies approval again. This replaces the known/unknown capability-settlement and owner-replacement requirements in ADRs 0001, 0003 and 0004: closure prevents further broker publication, but already-issued or lost tokens may remain valid until GitHub expiry, normally one hour from creation. The broker cannot individually revoke tokens it no longer holds.

Use one bounded current record per admitted repository and fixed minute counters, with conditional ETag writes fencing closure, expiry and replacement. Setup completion recovery remains encrypted only until acknowledgment or the original 15-minute deadline. Cleanup makes one paginated pass over due records every five minutes and retains only a small closed-generation fence. A fresh explicitly initialized schema-2 Table and fresh enrollment provide the cutover; old history is not migrated or reset in place. Shared-key separation, live repository approval, exact token scoping and permanent denial of closed enrollment IDs remain required.
